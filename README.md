# 당지킴 — 당뇨 식단 기록 & 영양교육 웹사이트

표준레시피 기반으로 하루 식단의 당류·영양성분을 계산하고, 영양판정(신체계측·생화학 수치·활동량·건강상태·목표)에 맞춰
하루 필요 열량과 끼니별 식단 예시를 제시하는 정적 웹사이트입니다. 서버 없이 GitHub Pages로 운영할 수 있습니다.

## 사용 흐름
처음 접속하면 질문 6단계(기본 정보 → 몸 상태 → 혈당 → 혈압·지질 → 생활 → 목표)에 답하고, 하루 목표가 나오면 바로 첫 끼니 기록으로 이어집니다.
평소에는 **오늘**(식판 게이지 + 다음 끼니 추천 → 한 번에 기록) → **기록**(음식 → 양 → 하나 더 / 다음 끼니) → **식단** → **내 정보** → **알아두기** 탭을 씁니다.

## 기능
| 탭 | 내용 |
|---|---|
| 오늘 | 당류 5점 만점 평가, 영양성분 합계(목표 대비), 끼니별 열량, 고당류 음식 대체 추천·권장량, 최근 7일 당류 그래프 |
| 식단 기록 | 끼니 선택 → 음식 검색(표준레시피 1인분) → 식사 전·후 사진으로 섭취량(¼~2인분) 확인 → 기록. 간식·과일·음료 포함, 직접 입력 가능 |
| 영양판정 | BMI·표준체중비·허리둘레, 혈당·HbA1c·지질·혈압 판정, EER 기반 목표 열량과 3대 영양소·당류 상한 |
| 식단 가이드 | 아침 25 / 점심 30 / 저녁 30 / 간식 15% 배분, 목표 열량에 맞춘 식단 예시와 양 |
| 영양교육 | 당뇨 식사요법, 숨은 당, 저혈당 대처 |

## 계산 기준
- **에너지필요추정량(EER)**: 2020 한국인 영양소 섭취기준 성인 공식 (19세 이상)
  - 남: 662 − 9.53×나이 + PA×(15.91×체중 + 539.6×키m) / PA 1.0·1.11·1.25·1.48
  - 여: 354 − 6.91×나이 + PA×(9.36×체중 + 726×키m) / PA 1.0·1.12·1.27·1.45
- **목표 보정**: 다이어트 EER−500kcal(최저 남 1500·여 1200), 근육증가 EER+300kcal
- **단백질**: 유지 0.91, 다이어트 1.2, 근육증가 1.6 g/kg (BMI 25 이상은 표준체중, 당뇨 최대 1.3, 신장질환 0.8 g/kg)
- **지방** 25%, **탄수화물** 나머지
- **당류 두 단계**: 앱 권장 = 총당류 에너지의 10%(2,000kcal면 50g, 첨가당 권고를 보수적으로 적용), 공식 상한 = 총당류 20%(KDRI 2025). 막대는 초록(권장 안)·노랑(권장 초과, 공식 상한 안)·빨강(공식 상한 초과). DB의 당류는 총당류(첨가당 구분 없음)
- **혈당 관리 점수**: 당류 점수와 탄수화물 점수의 평균(내림). 영양성분표의 '당류'는 단순당만 세고 밥·면·떡의 전분은 탄수화물로 집계되므로, 당류만 평가하면 쌀밥이 0g으로 나와 혈당 부담을 놓칩니다.
- **탄수화물 점수**: 목표 대비 ≤100% 5점, ≤110% 4점, ≤120% 3점, ≤135% 2점, 그 이상 1점. 끼니별 목표(25/30/30/15%)를 20% 넘으면 알림.
- **당류 점수**: 권장량 대비 ≤50% 5점, ≤75% 4점, ≤100% 3점, 공식 상한(권장의 2배)까지 2점, 초과 1점
- **음식별 권장량**: 한 음식의 당류가 하루 상한의 20%를 넘지 않도록 ¼ 단위로 계산

## GitHub Pages 배포
1. GitHub에서 새 저장소 생성 (예: `dangkeeper`)
2. 이 폴더의 파일을 모두 업로드 (Add file → Upload files) 또는
   ```bash
   git init && git add . && git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<아이디>/dangkeeper.git
   git push -u origin main
   ```
3. 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)** 저장
4. 1~2분 뒤 `https://<아이디>.github.io/dangkeeper/` 접속

- **혈당지수(GI)**: `js/foods.js`의 `GI`에 낮음/중간/높음 구분을 참고값으로 넣었습니다(점수에는 반영하지 않고 표시·알림에만 사용). 목록에 없는 음식은 표시하지 않습니다.

## 영양성분 출처
모든 음식(73종)의 영양성분은 식약처·농진청 공공데이터에서 가져왔고, 음식마다 출처가 화면에 표시됩니다. 값 = 100g(ml)당 값 × 1회 분량.
- **음식 44종**: 식약처 「전국통합식품영양성분정보(음식)표준데이터」 — 식품코드 표기.
  선택 우선순위: 가정식(분석) > 외식(분석) > 외식·급식(재료량 기반 산출) > 프랜차이즈.
- **과일·채소·닭가슴살·아몬드 15종**: 「식품영양성분DB정보(원재료성)」(국가표준식품성분표) — 식품코드 표기.
- **가공식품 14종**(초코파이·단팥빵·아이스크림·치즈·요거트·우유·두유·콜라·주스·보리차 등): 「식품영양성분DB정보(가공식품)」에서
  같은 대표식품 제품들의 **중앙값**(n 표기)을 사용했습니다. 제품마다 차이가 크니 실제 먹는 제품의 영양표시가 있으면 '직접 입력'을 쓰세요.
- 값이 비어 있는 항목(예: 식이섬유)은 기존 참고값을 유지했습니다.

## 라벨 사진으로 영양성분 자동 입력
식단 기록 → '목록에 없는 음식 직접 입력' → **영양성분표 사진으로 자동 입력**. 브라우저 안에서 한글 OCR(Tesseract.js)로 읽어 열량·탄수화물·당류·단백질·지방·식이섬유를 채웁니다.
- 사진은 서버로 전송되지 않습니다. 처음 사용할 때 OCR 모듈과 한글 인식 데이터를 CDN(jsdelivr)에서 내려받습니다(인터넷 필요, 몇 초).
- 표시 기준(100g당 / 1회 제공량 / 총 내용량)을 읽어서, 먹은 양을 입력하면 그 양으로 환산해 저장합니다.
- **읽은 숫자는 반드시 확인**하세요. 구겨지거나 반사된 사진은 오인식이 날 수 있고, '인식된 글자 보기'로 원문을 볼 수 있습니다.
- 해석 로직은 `js/label.js`의 `parse()`에 있습니다.

## 참고
- 기록은 **사용하는 기기의 브라우저(localStorage)** 에만 저장됩니다. 다른 기기와 공유되지 않으며, 브라우저 데이터를 지우면 사라집니다.
- 사진은 360px로 줄여 저장합니다. 사진에서 섭취량을 **자동 인식**하려면 이미지 인식 API(서버 필요)를 붙여야 하며, 현재는 식사 전·후 사진을 보고 섭취 비율을 고르는 방식입니다.
- 영양 정보는 추정치이며 의학적 진단·처방을 대신하지 않습니다.

## 신체 구성 · 목표 체중
- **인바디(선택)**: 체지방률로 체지방 판정(흔히 쓰는 기준 남 25%·여 30% 이상 과다, 남 20%·여 28% 이상 경계), BMI 정상인데 체지방 과다면 "마른 비만" 안내. 제지방량 = 체중 × (1 − 체지방률). 골격근량은 값과 체중 대비 비율만 표시.
- **단백질**: 체중 기준 유지 0.91·감량 1.2·근육 증가 1.6 g/kg(ISSN 1.4~2.0 g/kg 범위의 중간). 당뇨가 있으면 1.3 g/kg 이하(KDIGO 등 고단백 경고), 신장질환은 0.8 g/kg(대한당뇨병학회). 체지방률은 판정에만 쓰고 단백질 계산에는 쓰지 않음.
- **목표 체중·기간(선택)**: 하루 열량 조정 = 체중 변화(kg) × 7,700 ÷ (기간 × 7). 감량은 하루 −250~−1,000kcal, 증량은 +200~+500kcal로 제한하고 넘으면 경고와 실제 필요 기간을 표시.

## 일주일 식단 · 식비
- 좋아하는 음식 종류(한식·양식·일식·찌개·탕·덮밥·해산물·회·구이)를 고르면 그 태그가 붙은 예시를 우선 사용. 음식 36종을 식약처 음식DB에서 추가(총 109종).
- 일주일 식비를 정하면 7일 식단 비용을 계산하고, 넘으면 가장 비싼 끼니부터 한 단계 싼 예시로 바꿈. 가장 싼 조합으로도 넘으면 싼 예시 3개를 요일별로 돌려 쓰고 경고 표시.
- **가격은 추정치**: 공공데이터에 가격이 없어 `foods.js`의 `PRICE`에 직접 정함. 밥·국·반찬·과일은 집밥 재료비, 덮밥·초밥·탕·면 등 일품요리는 외식 1인분 기준.
- **밖에서 먹을 때**: 선호 종류에 맞는 검색어로 네이버지도·카카오맵 검색을 연결(식당 목록을 직접 보여주지는 않음).

## 식약처 DB 검색 음식 (`foods_db.js`)
- 기본 목록 109가지 외에 검색용으로 3,847가지를 넣었어요: 음식 DB 가정식·외식·급식 약 2,000가지 + 원재료 약 1,800가지. **프랜차이즈 메뉴는 제외**(사이즈별 중복이 많아, 필요하면 라벨 사진이나 직접 추가로 입력).
- 음식: 같은 이름은 가정식(분석) > 외식(분석) > 재료량 산출 순으로 하나만 남기고, 1인분은 DB의 식품중량(30~1,000g 밖이면 100g 기준).
- 원재료: 지역·월별 측정값은 '대표 평균'을 우선해 하나로 묶고 100g 기준.
- 검색어를 입력하거나 '식재료' 분류를 누를 때만 나오고, 한 번에 60개까지 보여 줘요. 혈당지수·가격 표시와 식단 예시는 기본 목록에만 있어요.
- 재생성: `build_db.py`처럼 CSV(cp949)를 읽어 같은 규칙으로 다시 만들 수 있어요.

## 내 몸 혈당 반응 · 진료용 리포트 · 빠른 기록
- **혈당 기록**: 기록 화면에서 끼니마다 식전(아침은 공복)·식후 2시간 혈당 입력. `dk_bg`에 저장.
- **음식별 혈당 반응**: 식후 혈당이 적힌 끼니의 음식 중 탄수화물 20g 이상인 것(밥·면·빵·과일 등)에 그 값을 붙여 평균. 2번 이상 먹은 음식만 순위에 올림. 함께 먹은 반찬·양·운동·약의 영향이 섞인 경향이라 원인으로 단정하지 않음.
- **식단 예시 반영**: 식후 평균 180mg/dL 이상(2회 이상)인 음식이 든 예시는 뒤로 미룸. 음식 고르기 목록에 "내 식후 평균" 표시.
- **리포트**: 최근 30/90일 하루 평균 섭취(목표 대비), 끼니별 탄수화물, 공복·식후 혈당 평균, 식후 180 미만 비율, 끼니 탄수화물 목표 초과 여부별 식후 혈당, 혈당을 많이/덜 올린 음식, 당류를 많이 준 음식. "PDF로 저장·인쇄"는 브라우저 인쇄(내비게이션·버튼 숨김).
- **자주 먹은 끼니**: 최근 60일 같은 음식·양 조합을 세어 한 번 누르면 그대로 기록. 오늘 화면에도 "늘 먹던 대로"(2번 이상) 버튼.
- **가족에게 보내기**: 하루 기록·혈당·점수를 글로 만들어 휴대폰 공유창(카카오톡 등)으로 보냄. 공유창이 없으면 클립보드에 복사.
- 하단 메뉴: 오늘 · 기록 · 식단 · 리포트 · 내 정보 (알아두기는 내 정보·리포트 아래에서).

## 앱 설치(PWA)와 백업
- 안드로이드 크롬에서 사이트를 한 번 열면 서비스 워커가 파일을 저장해 오프라인에서도 열립니다.
- 내 정보 → "홈 화면에 앱 설치" 버튼(또는 크롬 ⋮ → 앱 설치/홈 화면에 추가)으로 설치합니다.
- 글꼴(Pretendard CDN)과 라벨 사진 인식(OCR)은 인터넷이 필요합니다.
- 기록은 기기 안(localStorage)에만 저장됩니다. 내 정보 → "기록 백업 파일 저장"으로 JSON을 내려받고, 같은 화면에서 불러올 수 있습니다.
- 파일을 수정해 올릴 때는 index.html의 `?v=` 값과 sw.js의 CACHE 이름을 함께 바꿔야 새 버전이 반영됩니다.

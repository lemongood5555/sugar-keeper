# 당지킴 — 당뇨 식단 기록 & 영양교육 웹사이트

표준레시피 기반으로 하루 식단의 당류·영양성분을 계산하고, 영양판정(신체계측·생화학 수치·활동량·건강상태·목표)에 맞춰
하루 필요 열량과 끼니별 식단 예시를 제시하는 정적 웹사이트입니다. 서버 없이 GitHub Pages로 운영할 수 있습니다.

## 사용 흐름
처음 접속하면 질문 6단계(기본 정보 → 몸 상태 → 혈당 → 혈압·지질 → 생활 → 목표)에 답하고, 하루 목표가 나오면 바로 첫 끼니 기록으로 이어집니다.
평소에는 **오늘**(식판 게이지 + 다음 끼니 추천 → 한 번에 기록) → **기록**(음식 → 양 → 하나 더 / 다음 끼니) → **식단** → **내 정보** → **알아두기** 탭을 씁니다.

## 기능
| 탭 | 내용 |
|---|---|
| 오늘 | 당류 5점 만점 평가, 영양성분 합계(목표 대비), 끼니별 열량, 고당류 음식 대체 추천·권장량, 최근 7일 당류 그래프 |
| 식단 기록 | 끼니 선택 → 음식 검색(표준레시피 1인분) → 식사 전·후 사진으로 섭취량(¼~2인분) 확인 → 기록. 간식·과일·음료 포함, 직접 입력 가능 |
| 영양판정 | BMI·표준체중비·허리둘레, 혈당·HbA1c·지질·혈압 판정, EER 기반 목표 열량과 3대 영양소·당류 상한 |
| 식단 가이드 | 아침 25 / 점심 30 / 저녁 30 / 간식 15% 배분, 목표 열량에 맞춘 식단 예시와 양 |
| 영양교육 | 당뇨 식사요법, 숨은 당, 저혈당 대처 |

## 계산 기준
- **에너지필요추정량(EER)**: 2020 한국인 영양소 섭취기준 성인 공식 (19세 이상)
  - 남: 662 − 9.53×나이 + PA×(15.91×체중 + 539.6×키m) / PA 1.0·1.11·1.25·1.48
  - 여: 354 − 6.91×나이 + PA×(9.36×체중 + 726×키m) / PA 1.0·1.12·1.27·1.45
- **목표 보정**: 다이어트 EER−500kcal(최저 남 1500·여 1200), 근육증가 EER+300kcal
- **단백질**: 유지 0.91, 다이어트 1.2, 근육증가 1.4 g/kg (BMI 25 이상은 표준체중, 신장질환은 0.8 g/kg)
- **지방** 25%, **탄수화물** 나머지
- **당류 상한**: 엄격 10%(당뇨 기본) / 일반 20% — 2020 KDRI 총당류 10~20%
- **혈당 관리 점수**: 당류 점수와 탄수화물 점수의 평균(내림). 영양성분표의 '당류'는 단순당만 세고 밥·면·떡의 전분은 탄수화물로 집계되므로, 당류만 평가하면 쌀밥이 0g으로 나와 혈당 부담을 놓칩니다.
- **탄수화물 점수**: 목표 대비 ≤100% 5점, ≤110% 4점, ≤120% 3점, ≤135% 2점, 그 이상 1점. 끼니별 목표(25/30/30/15%)를 20% 넘으면 알림.
- **당류 점수**: 권장량 대비 ≤50% 5점, ≤75% 4점, ≤100% 3점, ≤125% 2점, 그 이상 1점
- **음식별 권장량**: 한 음식의 당류가 하루 상한의 20%를 넘지 않도록 ¼ 단위로 계산

## GitHub Pages 배포
1. GitHub에서 새 저장소 생성 (예: `dangkeeper`)
2. 이 폴더의 파일을 모두 업로드 (Add file → Upload files) 또는
   ```bash
   git init && git add . && git commit -m "first commit"
   git branch -M main
   git remote add origin https://github.com/<아이디>/dangkeeper.git
   git push -u origin main
   ```
3. 저장소 **Settings → Pages → Source: Deploy from a branch → main / (root)** 저장
4. 1~2분 뒤 `https://<아이디>.github.io/dangkeeper/` 접속

- **혈당지수(GI)**: `js/foods.js`의 `GI`에 낮음/중간/높음 구분을 참고값으로 넣었습니다(점수에는 반영하지 않고 표시·알림에만 사용). 목록에 없는 음식은 표시하지 않습니다.

## 영양성분 출처
모든 음식(73종)의 영양성분은 식약처·농진청 공공데이터에서 가져왔고, 음식마다 출처가 화면에 표시됩니다. 값 = 100g(ml)당 값 × 1회 분량.
- **음식 44종**: 식약처 「전국통합식품영양성분정보(음식)표준데이터」 — 식품코드 표기.
  선택 우선순위: 가정식(분석) > 외식(분석) > 외식·급식(재료량 기반 산출) > 프랜차이즈.
- **과일·채소·닭가슴살·아몬드 15종**: 「식품영양성분DB정보(원재료성)」(국가표준식품성분표) — 식품코드 표기.
- **가공식품 14종**(초코파이·단팥빵·아이스크림·치즈·요거트·우유·두유·콜라·주스·보리차 등): 「식품영양성분DB정보(가공식품)」에서
  같은 대표식품 제품들의 **중앙값**(n 표기)을 사용했습니다. 제품마다 차이가 크니 실제 먹는 제품의 영양표시가 있으면 '직접 입력'을 쓰세요.
- 값이 비어 있는 항목(예: 식이섬유)은 기존 참고값을 유지했습니다.

## 데이터 수정
- 음식 추가·수정: `js/foods.js`의 `FOODS` 배열
- 대체 음식: `ALTERNATIVES`, 식단 예시: `MEAL_TEMPLATES`
- 판정 기준·목표 계산: `js/nutrition.js`

## 라벨 사진으로 영양성분 자동 입력
식단 기록 → '목록에 없는 음식 직접 입력' → **영양성분표 사진으로 자동 입력**. 브라우저 안에서 한글 OCR(Tesseract.js)로 읽어 열량·탄수화물·당류·단백질·지방·식이섬유를 채웁니다.
- 사진은 서버로 전송되지 않습니다. 처음 사용할 때 OCR 모듈과 한글 인식 데이터를 CDN(jsdelivr)에서 내려받습니다(인터넷 필요, 몇 초).
- 표시 기준(100g당 / 1회 제공량 / 총 내용량)을 읽어서, 먹은 양을 입력하면 그 양으로 환산해 저장합니다.
- **읽은 숫자는 반드시 확인**하세요. 구겨지거나 반사된 사진은 오인식이 날 수 있고, '인식된 글자 보기'로 원문을 볼 수 있습니다.
- 해석 로직은 `js/label.js`의 `parse()`에 있습니다.

## 참고
- 기록은 **사용하는 기기의 브라우저(localStorage)** 에만 저장됩니다. 다른 기기와 공유되지 않으며, 브라우저 데이터를 지우면 사라집니다.
- 사진은 360px로 줄여 저장합니다. 사진에서 섭취량을 **자동 인식**하려면 이미지 인식 API(서버 필요)를 붙여야 하며, 현재는 식사 전·후 사진을 보고 섭취 비율을 고르는 방식입니다.
- 영양 정보는 추정치이며 의학적 진단·처방을 대신하지 않습니다.
